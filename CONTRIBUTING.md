# Contributing Guide For NZC-Assist

This page lists the governance model and contribution expectations for NZC-Assist.

## Governance Model

### Salesforce Sponsored

The goal of open sourcing this project is to increase the contributor and user base.
Salesforce employees maintain final approval authority for contributions.

## Getting Started

- Open a discussion through GitHub Issues before starting non-trivial changes.
- Keep pull requests focused, small, and reviewable.
- Ensure changes align with the repository roadmap and project goals.

## Issues, Requests, and Ideas

- Search existing issues first: [Issues](https://github.com/salesforce-misc/NZC-Assist/issues)
- Create new issues for bugs, feature requests, or documentation improvements.
- Link pull requests to their related issue(s).

## Contribution Checklist

- Clean, maintainable code
- Descriptive commit messages
- Tests added/updated as needed
- Dependencies minimized and license-compatible
- Peer review completed before merge

## Creating a Pull Request

1. Confirm there is an issue (existing or new) describing the change.
2. Fork and clone the repository.
3. Create a dedicated branch for your work.
4. Commit and push your changes.
5. Open a pull request against `main` and reference related issues.
6. Complete Salesforce CLA if prompted.
