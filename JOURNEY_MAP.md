# Salesforce Net Zero Cloud — Journey Map & Setup Sequence

> Reference blueprint for the **claude-for-net-zero** plugin.
> Sources: Net Zero Cloud Developer Guide (`developer.salesforce.com/docs/atlas.en-us.netzero_cloud_dev_guide.meta/netzero_cloud_dev_guide/`) — curated links in `documentation/README.md`.
> Last revised: 2026-09-29.

This doc has two parts:

1. **High-level Journey Map** — the per-domain "user journey" sheet, used to scope skills/commands/agents.
2. **Object-Level Setup Sequence** — the dependency-ordered list, used as the canonical ordering for any setup wizard, audit, or scaffolding command.

Object and field API names below reflect the plugin's design-time model. **Always confirm the current org's actual API names via `describe_sobject` before writing SOQL or CSV headers** — Net Zero Cloud names drift across releases (see `CLAUDE.md` § "Always `describe_sobject`").

---

## Part 1 — High-Level Journey Map

| # | Journey | Key Concepts | Primary Objects / Settings | Plugin Surface (proposed) |
|---|---|---|---|---|
| 1 | **Foundation & Licensing** | Net Zero Cloud requires a provisioned license before any NZC object or settings field exists. Data Processing Engine (DPE) license is required for footprint calculation. TCRM-for-Sustainability license layers admin/user access. No self-service enablement — Salesforce provisions the org. | Permission Set Licenses: `NetZeroCloudUserPsl`, `DataProcessingEnginePsl`, `TCRMforSustainabilityPsl`. Detection probe: `describe_sobject StnryAssetEnvrSrc`. | `/nzc:setup-plugin`, `/nzc:status`, `nzc-foundation-licensing` skill |
| 2 | **Permissions & Access** | Foundation PSL is mandatory; DPE and TCRM PSLs layered on top per role. Standard permission sets assign object/field-level access on top of PSLs — PSLs alone do not grant CRUD. | Permission sets: `NetZeroManager`, `DataProcessingEngineUser`, `TCRMforSustainabilityAdmin`, `TCRMforSustainabilityUser`. | `/nzc:assign-permissions`, `/nzc:audit` (PSL/permset coverage), `nzc-foundation-licensing` skill |
| 3 | **Data Model** | Industry-specific objects layered on a reference → source → periodic use → footprint → annual inventory pipeline. Every domain (stationary, vehicle, waste, water, Scope 3) follows the same source/use/footprint shape and rolls up into one inventory per fiscal year. | Core pipeline objects: `AnnualEmssnInventory`, source objects (`StnryAssetEnvrSrc`, `VehicleAssetEmssnSrc`, `Scope3EmssnSrc`), use objects (`StnryAssetEnrgyUse`, `VehicleAssetEnrgyUse`, `GeneratedWaste`, `StnryAssetWaterActvty`, `Scope3PcmtItem`, `AirTravelEnrgyUse`, `HotelStayEnrgyUse`, `RentalCarEnrgyUse`), footprint objects (`StnryAssetCrbnFtprnt`, `VehicleAssetCrbnFtprnt`, `WasteFootprint`, `StnryAssetWaterFtprnt`, `Scope3CrbnFtprnt`). | `nzc-data-model` skill, `/nzc:describe`, `/nzc:soql-query` |
| 4 | **Industries / Sustainability Settings** | Org-wide feature flags gate which NZC domains are active. Most are one-way once turned on. Some flags may only be togglable in Setup UI depending on release — the plugin deploys what it can via metadata and reports the rest. | `Industries.settings` metadata, `enableSC*` flags (stationary assets, vehicle assets, waste, water, Scope 3 procurement, Scope 3 travel). | `/nzc:enable-net-zero`, `nzc-foundation-licensing` skill |
| 5 | **Record Types & Config Metadata** | Source objects are split by record type per domain; `*Config` custom metadata types drive downstream calculation behavior (e.g. which building-intensity benchmark applies). Deployed as metadata, never created via SOQL/DML. | `StnryAssetEnvrSrc` RTs (`Commercial_Building`, `Data_Center`); `VehicleAssetEmssnSrc` RTs (`Fleet_Vehicle`, `Private_Jet`); `BldgEnrgyIntensity` RTs (`Building_Energy_Intensity`, `Regional_Building_Energy_Intensity`); custom metadata `stationaryAssetEnvSourceConfigs`, `vehicleAssetEmssnSourceConfigs`, `buildingEnergyIntensityConfigs`. | `/nzc:configure-record-types`, `nzc-data-model` skill |
| 6 | **Reference & Emission Factor Data** | Published emission factors (electricity grid factors, fuel factors, refrigerants, waste disposal, procurement spend-based factors, travel factors) must exist before any source can compute a footprint. Scope allocation and inflation rate metadata normalize factors across scopes and years. Committed as seed data — **never fabricated**. | `ElectricityEmssnFctrSet`, `OtherEmssnFctrSet`/`OtherEmssnFctrItem`, `RefrigerantEmssnFctr`, `WstDispoEmssnFctrSet`/`WstDispoEmssnFctrItm`, `PcmtEmssnFctrSet`/`PcmtEmssnFctrItem`, air/hotel/rental/ground travel factor sets, `CrbnEmssnScopeAlloc`/`CrbnEmssnScopeAllocVal`, `InflationRate`, `UnitOfMeasure`/UOM conversions, `FuelType`. | `/nzc:load-reference-data`, `nzc-reference-data` skill |
| 7 | **Stationary Assets / Buildings** | Buildings and data centers as emission sources. Building size category + building energy intensity benchmarks let footprint calculation estimate consumption when metered data is incomplete. | `StnryAssetEnvrSrc`, `StnryAssetEnrgyUse`, `BldgSizeCategory`, `BldgEnrgyIntensity`/`BldgEnrgyIntensityVal`. | `nzc-stationary-buildings` skill, `/nzc:configure-stationary-assets` |
| 8 | **Vehicles / Fleet** | Fleet vehicles and private aircraft as mobile emission sources, tracked by periodic fuel/energy use. | `VehicleAssetEmssnSrc`, `VehicleAssetEnrgyUse`, `VehicleAssetCrbnFtprnt`. | `nzc-vehicles-fleet` skill, `/nzc:configure-vehicles` |
| 9 | **Waste** | Waste generation at a stationary source, disposed via multiple methods (landfill, recycling, composting, incineration), each with its own emission factor. | `GeneratedWaste`, `WstDispoEmssnFctrSet`/`WstDispoEmssnFctrItm`, `WasteFootprint`/`WasteFootprintItem`. | `nzc-waste` skill, `/nzc:configure-waste` |
| 10 | **Water** | Water withdrawal/discharge activity tied to a stationary source, rolled into a water footprint. | `StnryAssetWaterActvty`, `StnryAssetWaterFtprnt`/`StnryAssetWaterFtprntItem`. | `nzc-water` skill, `/nzc:configure-water` |
| 11 | **Scope 3 — Procurement** | Purchased goods/services emissions via the spend-based method: supplier + procurement line items priced against category-level spend-based factors, inflation-normalized. | `Scope3EmssnSrc`, `Scope3PcmtItem`, `PcmtEmssnFctrSet`/`PcmtEmssnFctrItem`, `Supplier`, `InflationRate`. | `nzc-scope3-procurement` skill, `/nzc:configure-scope3-procurement` |
| 12 | **Scope 3 — Business Travel** | Employee business travel emissions: air travel, hotel stays, rental cars, and (optionally) ground travel, each with its own energy-use object and factor set. | `Scope3EmssnSrc`, `AirTravelEnrgyUse`, `HotelStayEnrgyUse`, `RentalCarEnrgyUse`, `GroundTravelEnrgyUse` (optional). | `nzc-scope3-travel` skill, `/nzc:configure-scope3-travel` |
| 13 | **Annual Emissions Inventory** | The umbrella container for a fiscal year's emissions. Every footprint record must link back to one. Must exist before any footprint calculation runs. | `AnnualEmssnInventory`. | `nzc-annual-inventory` skill, `/nzc:build-annual-inventory` |
| 14 | **Carbon Footprint Calculation** | Rolls up periodic energy/activity use against the matching emission factors into per-source footprints, linked to the annual inventory. Typically a Data Processing Engine batch job or a Setup UI action rather than a synchronous API call — v1 loads/derives coherent footprint data and documents the DPE/UI path. | `StnryAssetCrbnFtprnt`/`Itm`, `VehicleAssetCrbnFtprnt`, `WasteFootprint`/`Item`, `StnryAssetWaterFtprnt`/`Item`, `Scope3CrbnFtprnt`, DPE `BatchCalcJobDefinition`. | `nzc-carbon-footprint-calc` skill, `/nzc:calculate-footprints` |
| 15 | **Targets, Forecasting, Carbon Credits & ESG Disclosure** *(later phase — not in v1)* | Science-based/custom emission-reduction targets, forecasting against historical inventories, carbon credit/offset purchases, and ESG disclosure reporting. Explicitly out of scope for v1 (data & config only, per the confirmed scope decision). | Target, forecast, and carbon-credit objects (TBD when this phase is scoped). | *(not authored in v1 — noted in `knowledge/modules/INDEX.md` as future work)* |
| 16 | **Testing & Go-Live (SDET)** | Repeatable sample-data scaffolding (hybrid seed + runtime generation) and teardown; count/integrity validation; audit automation against the rule library. Production-write safety: the plugin must refuse destructive/bulk-write operations by default against any org until explicitly confirmed. | Fixture manifests (created-ID tracking for reverse-order teardown), `knowledge/validation-rules/*.yaml`. | `nzc-testing-validation` skill, `nzc-sdet` agent, `/nzc:scaffold-sample-data`, `/nzc:audit`, `/nzc:health-check` — **primary surface for the SDET persona** |

## Part 2 — Object-Level Setup Sequence (Dependency Order)

> Steps are *one-way prerequisites* — never reverse the order. Bold steps map to "provisioned by Salesforce / org-wide toggle, confirm before touching."

| # | Step | Why this position | Source |
|---|---|---|---|
| 1 | **NZC license provisioned** (detect via `describe_sobject StnryAssetEnvrSrc`; confirm DPE + TCRM-for-Sustainability licenses via `SELECT DeveloperName FROM PermissionSetLicense WHERE DeveloperName LIKE '%NetZero%' OR DeveloperName LIKE '%Sustainability%'`) | Nothing below exists in an unlicensed org — no NZC object, field, or settings flag is visible. Must stop here if absent. | NZC Dev Guide: Get Started |
| 2 | **Permission Set Licenses** (`NetZeroCloudUserPsl`, `DataProcessingEnginePsl`, `TCRMforSustainabilityPsl`) | PSLs gate feature visibility org-wide; permission sets layered later cannot grant access to a PSL-gated feature the user lacks. | NZC Dev Guide: Permissions |
| 3 | **Permission sets** (`NetZeroManager`, `DataProcessingEngineUser`, `TCRMforSustainabilityAdmin`, `TCRMforSustainabilityUser`) | Object/field-level CRUD on top of PSLs. Without these, licensed users still can't see NZC data. | NZC Dev Guide: Permissions |
| 4 | **Industries / Sustainability settings** (all relevant `enableSC*` flags in `Industries.settings`) | Each domain (stationary, vehicle, waste, water, Scope 3) is gated by its own flag. Record types and `*Config` metadata for a domain can't be meaningfully used until its flag is on. | NZC Dev Guide: Settings |
| 5 | **Record types** (`StnryAssetEnvrSrc`: `Commercial_Building`/`Data_Center`; `VehicleAssetEmssnSrc`: `Fleet_Vehicle`/`Private_Jet`; `BldgEnrgyIntensity`: `Building_Energy_Intensity`/`Regional_Building_Energy_Intensity`) | Source records need a record type before they can be meaningfully created; page layouts and `*Config` metadata key off record type. | NZC Dev Guide: Data Model |
| 6 | **`*Config` custom metadata** (`stationaryAssetEnvSourceConfigs`, `vehicleAssetEmssnSourceConfigs`, `buildingEnergyIntensityConfigs`) | Drives footprint-calculation behavior per record type. Must exist before real source data is calculated against it. | NZC Dev Guide: Data Model |
| 7 | **UOM conversions + `FuelType`** | Every energy-use quantity is recorded in a unit of measure that must convert cleanly to the unit an emission factor expects. Fuel types classify vehicle/stationary fuel records before factor sets can be matched to them. | NZC Dev Guide: Emissions Data |
| 8 | **Emission factor sets + items + `CrbnEmssnScopeAlloc`(+`Val`) + `InflationRate`** | The actual published factors (electricity, fuel, refrigerant, waste disposal, procurement, travel) plus scope allocation and inflation normalization. Nothing downstream can compute a footprint without these. | NZC Dev Guide: Emissions Data |
| 9 | **`BldgSizeCategory` + `BldgEnrgyIntensity`(+`Val`)** | Building energy intensity benchmarks used to estimate stationary consumption when metered data is incomplete. Depends on record types from step 5. | NZC Dev Guide: Data Model |
| 10 | **Accounts + Suppliers** | Sources (buildings, vehicles, procurement) are typically owned by or associated with an account; Scope 3 procurement sources require suppliers to exist first. | NZC Dev Guide: Data Model |
| 11 | **`AnnualEmssnInventory`** (one per fiscal year) | The umbrella container every footprint must reference. Must exist before any source or footprint is created against it. | NZC Dev Guide: Data Model |
| 12 | **Sources** (`StnryAssetEnvrSrc`, `VehicleAssetEmssnSrc`, `Scope3EmssnSrc`) | Depends on record types (5), `*Config` (6), and accounts/suppliers (10). Sources are the anchor every periodic-use record threads off of. | NZC Dev Guide: Data Model |
| 13 | **Periodic energy / activity use** (`StnryAssetEnrgyUse`, `VehicleAssetEnrgyUse`, `GeneratedWaste`, `StnryAssetWaterActvty`, `Scope3PcmtItem`, `AirTravelEnrgyUse`, `HotelStayEnrgyUse`, `RentalCarEnrgyUse`) | Depends on sources (12) existing and factor sets (8) being loaded so the quantities recorded here can later be priced against a factor. | NZC Dev Guide: Emissions Data |
| 14 | **Carbon footprints** (`StnryAssetCrbnFtprnt`(+`Itm`), `VehicleAssetCrbnFtprnt`, `WasteFootprint`(+`Item`), `StnryAssetWaterFtprnt`(+`Item`), `Scope3CrbnFtprnt`) — every record must carry a non-null `AnnualEmssnInventoryId` | Final rollup. Requires every prior step: factors, sources, periodic use, and the annual inventory (11) to already exist. | NZC Dev Guide: Emissions Data |
| 15 | **Targets / forecast / carbon credits / ESG disclosure** — **last / later phase, not in v1** | Depends on one or more complete annual inventories to forecast or target against. Explicitly excluded from v1 scope. | NZC Dev Guide: (future work) |
